# deploy

Артефакты развёртывания узла: образ, локальный кластер из трёх узлов и пример конфигурации.

## Запуск локального кластера

```powershell
pwsh scripts/build.ps1          # собрать образ узла
pwsh scripts/run-cluster.ps1    # поднять три узла и дождаться готовности
pwsh scripts/stop-cluster.ps1   # остановить и убрать контейнеры
```

Все три скрипта идемпотентны: повторный запуск не падает и не оставляет мусор.
`stop-cluster.ps1` по умолчанию сохраняет данные узлов (на S1 у узла появится диск,
и потеря данных между перезапусками не должна быть побочным эффектом остановки);
`-RemoveData` удаляет их явно.

## Порты

| Узел | Порт на хосте | Порт в контейнере |
| --- | --- | --- |
| node-a | 5001 | 8080 |
| node-b | 5002 | 8080 |
| node-c | 5003 | 8080 |

Внутри кластера узлы обращаются друг к другу по именам сервисов (`node-b:8080`),
поэтому внутренний порт у всех один, а на хосте порты разведены, чтобы можно было
подключиться к конкретному узлу снаружи.

## Формат конфигурации узла

Введён на S0-T07, загружается на S4-T05. Пример - `node-config.example.json`.

| Поле | Смысл |
| --- | --- |
| `schemaVersion` | Версия формата. Старый конфиг должен отвергаться понятной ошибкой, а не читаться наполовину |
| `nodeId` | Идентификатор этого узла (те же правила, что у типа `NodeId`) |
| `port` | Порт, который узел слушает |
| `peers` | Остальные узлы кластера, **без самого себя**: узел, считающий себя пиром, - ошибка конфигурации |

Значения переменных окружения с префиксом `RaftBroker__` переопределяют поля файла
(решение этапа S4-T05: файл имеет приоритет над умолчаниями, env - над файлом).
Сейчас, до S4-T05, узел читает только переменные окружения:

| Переменная | Пример |
| --- | --- |
| `RaftBroker__NodeId` | `node-a` |
| `RaftBroker__Port` | `8080` |
| `RaftBroker__Peers` | `node-b=node-b:8080,node-c=node-c:8080` |

Плохая конфигурация валит старт до открытия порта с текстом, в котором указано,
какая настройка не годится и почему.

## Коды возврата узла

| Код | Смысл |
| --- | --- |
| 0 | Узел отработал и остановился штатно |
| 2 | Конфигурация узла не принята (в stderr - какая настройка и почему) |
| 3 | Узел не смог занять свой порт |

Отдельный код на занятый порт нужен потому, что исключение из фоновой задачи хост
по умолчанию (StopHost) логирует и проглатывает: без явного кода узел, которому не
досталось порта, завершался бы с успехом. Это проверяется тестом
`NodeProcessTests.Node_WithOccupiedPort_FailsInsteadOfPretendingToBeUp`.
