# S2-T01 - Модель состояния узла: durable против volatile

- Этап: S2 - Raft: роли, term и выборы
- Статус: open
- Зависит от: `S0-T05` (примитивы `Term`/`LogIndex`/`NodeId`, done)
- Спецификация этапа: `docs/stages/02 - Raft roles and elections.md`
- Гейт: `pwsh scripts/verify.ps1`

## Что сделать

Завести в `src/RaftBroker.Raft/` типы состояния узла и роль; в `src/RaftBroker.Storage/HardState/` - `HardState`
и контракт `IHardStateStore` (реализация - `S2-T02`). Разделение durable/volatile должно быть видно компилятору,
а не подразумеваться комментарием: у durable-полей нет публичных сеттеров.

`ILogStore.TruncateSuffixAsync`/`ReplayAsync` и прочая механика журнала здесь не трогаются - задача только про
модель состояния.

## DoD (из плана)

Таблица полей с признаком «переживает рестарт» в спецификации; тест ловит изменение durable поля без записи на диск.

## Таблица durable/volatile (дублируется XML-doc на типе состояния)

| Поле | Тип | На диске | Почему |
|---|---|---|---|
| `CurrentTerm` | `Term` | да, fsync до ответа на RPC | иначе повторное голосование в том же term (R6) |
| `VotedFor` | `NodeId?` | да, fsync до ответа на RPC | то же |
| `CommitIndex` | `LogIndex` | нет (выводится из кворума) | unsafe хранить как истину |
| `LastApplied` | `LogIndex` | нет (истина в снапшоте) | восстанавливается из снапшота и реплея |
| `Role` | `RaftRole` | нет | при старте всегда `Follower` |
| `LeaderId` | `NodeId?` | нет | подсказка, не истина |
| `NextIndex`, `MatchIndex` | по пиру | нет | пересчитываются лидером |

## Как DoD проверяется тестом

Durable-поля меняются только через один метод, который сначала пишет `IHardStateStore.WriteAsync` и лишь после
успешной записи меняет память. Тесты:

1. Рефлексия по свойствам состояния: множество «без публичного сеттера» обязано совпасть с множеством durable
   полей из таблицы. Новое поле с сеттером или без сеттера валит тест - это и есть «тест ловит изменение
   durable поля без записи на диск».
2. Подменное хранилище считает записи: успешное изменение durable-пары = ровно один `WriteAsync`; провалившийся
   `WriteAsync` не меняет состояние в памяти (иначе после рестарта память и диск разъедутся).
3. Старт с пустого хранилища даёт `CurrentTerm = 0`, `VotedFor = null`, `Role = Follower`.

## Что уже есть под руками

- `Term`, `LogIndex`, `NodeId` (`RaftBroker.Core.Primitives`); `Term` начинается с `0`, `LogIndex.Empty` = `0`.
- Ранги слоёв: `Core` 0, `Storage` 1, `Raft` 2, `StateMachine` 3. `Raft` может ссылаться на `Storage` и не может
  на `StateMachine` (`tests/RaftBroker.UnitTests/Architecture/LayerReferenceTests.cs`).
- `RaftBroker.Raft.csproj` уже ссылается на `Core` и `Storage`; проект пустой.

## Ловушки

- `VotedFor` - `NodeId?`, а не `NodeId.Zero`: «не голосовал» и «голосовал за узел 0» - разные состояния.
- Не заводить `CurrentTerm++` сбоку: смена term обязана идти через persist, иначе `S2-T08` не соберёт матрицу
  переходов.
- Тест с рефлексией не должен зависеть от порядка полей - сравнивать множества.
- Покрытие 98.5%: каждая ветка нового типа (валидация, отказ записи) идёт вместе с тестом.
