# S2-T06 - Лидер: `nextIndex`/`matchIndex`, немедленный heartbeat, no-op запись

- Этап: S2 - Raft: роли, term и выборы
- Статус: open
- Зависит от: `S2-T05` (кандидат и победа)
- Спецификация этапа: `docs/stages/02 - Raft roles and elections.md`
- Гейт: `pwsh scripts/verify.ps1`

## Что сделать

Состояние и ритм лидера. Репликации ещё нет (`AppendEntries` на этом этапе несёт только term, сброс таймера и
пустой heartbeat; проверка логов - `S3-T01`), поэтому задача про инициализацию и таймеры, а не про пересылку записей.

1. При победе: `LeaderId = self`, `nextIndex[peer] = LastIndex + 1`, `matchIndex[peer] = 0` для каждого пира.
2. Немедленный heartbeat всем пирам, не дожидаясь первого интервала.
3. No-op запись своего term сразу после победы (подтверждено владельцем 2026-09-28 как осознанный выбор): снимает
   вопрос «закоммичено ли что-то из прошлых term» (§5.4.2) до появления правила коммита в S3.
4. Периодический heartbeat по `IClock`, интервал заметно меньше `T` (обычно `T/3`).
5. Сбор ответов для CheckQuorum - здесь только хранение, решение в `S2-T09`.

## DoD (из плана)

Тест: лидер инициализирует репликаторы, отправляет heartbeat немедленно и добавляет no-op запись в новом term.

## Что уже есть под руками

- `ILogStore.AppendAsync` (S1). Режим `GroupCommit` - на commit-пути Raft; `PerEntry` и `Periodic` запрещены
  ADR `0004` (допустимы только в тестах, где нужна детерминированность fsync).
- `LogRecordType` уже существует - сверить набор значений; если для no-op типа нет, его добавление меняет формат на
  диске, значит `docs/formats/log-segment.md` и ADR обновляются **до** кода.
- `IPeerTransport` и in-proc реализация из `S2-T05`.

## Как проверять

- После победы: `nextIndex = LastIndex + 1` и `matchIndex = 0` для всех пиров, `LeaderId = self`.
- Первый heartbeat уходит до истечения интервала (счётчик отправок на `TestClock`).
- No-op запись: одна, term нового лидера, индекс `LastIndex + 1`, payload пуст; повторная победа в новом term
  добавляет ещё одну.
- Heartbeat не сбрасывает собственный таймер выбора лидера (лидер не выбирает сам себя).
- После `StepDown` отправок нет: heartbeat-таймер остановлен, задачи репликаторов отменены.
- `pwsh scripts/verify.ps1`.

## Ловушки

- `matchIndex` инициализируется нулём, а не `LastIndex`: «совпало» - подтверждение, а не допущение.
- No-op не писать в обход очереди писателя (`S1-T08`), иначе конкурентная запись перемешается.
- Heartbeat - это `AppendEntries` с пустым `entries`, а не отдельный RPC (`proto/raft.proto`); поля формы запроса
  заполняются уже сейчас, проверок `prev_log_index` на этом этапе нет.
- Повисшая задача репликатора, пишущая в транспорт после `StepDown`, - утечка; `S2-T10` поймает её как «два лидера».

## Открытые вопросы

- Новое значение `LogRecordType` → `docs/formats/log-segment.md` плюс ADR и тест, что чтение старого сегмента
  не ломается.
